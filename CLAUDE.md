# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

Peekaboo: a camera-first social app for close friends (stories, disappearing "peeks", chat, daily dare, daily drop, Guess Who, hit ups, friend map). Expo SDK 58 + expo-router + TypeScript on the client, Supabase (Postgres + RLS + Storage + one Edge Function) as the whole back end. The owner is non-technical: user-facing copy and code comments are written in plain, simple English – keep that style.

## Commands

```sh
npm install
npx expo start               # dev server (Expo Go); add --clear after changing .env
npm run typecheck            # tsc --noEmit
npm run lint                 # expo lint (eslint-config-expo)
npx expo install --check     # native package versions must match the SDK – see "Native builds"
node scripts/sync-legal.mjs  # after editing anything in legal/ (regenerates src/lib/legalDocs.ts)
```

There is no automated test suite; `docs/TESTING.md` is the manual, per-feature test script. Validate changes with typecheck + lint.

`.env` (gitignored, see `.env.example`) holds `EXPO_PUBLIC_SUPABASE_URL` and `EXPO_PUBLIC_SUPABASE_PUBLISHABLE_KEY`. Without them `src/lib/supabase.ts` points at a dummy host and the root layout shows the `SetupNeeded` screen instead of crashing.

## Architecture

- **Routing** (`src/app`): `_layout.tsx` wraps everything in gesture/theme/`OverlayProvider` (toasts, sheets) and `AuthProvider`, then switches between the logged-out screens (`welcome`, `sign-in`, `sign-up`, `legal/`) and the `(app)` group. `(app)/_layout.tsx` gates on terms acceptance (`TermsGate`) and schedules local drop notifications.
- **Home** (`(app)/index.tsx`): a `PagerView` with Chat ← Camera → Home. The camera page (`components/home/CameraPage.tsx`) has a `ModeDial` of mode bubbles (googly lens, dare, Guess Who) above the shutter; the shutter ring colour follows the mode. `CameraPage` is reused for chat cameras (`sendTo`) and for dare/drop/forfeit/guess cameras via props.
- **Capture flow**: camera → `editor.tsx` (filters, text, stickers; flattened with `react-native-view-shot`) → `share.tsx` ("Send to…": story / profile / friends / dare / drop / guess). Mode context travels as route params (`to`, `dare`, `drop`, `guess`, `forfeit`). From a chat camera (`to` only) the editor sends the peek directly and skips `share`.
- **Data layer** (`src/lib`): one module per feature (`posts.ts`, `stories.ts`, `chat.ts`, `friends.ts`, `hitups.ts`, `dares.ts`, `drop.ts`, …) that calls Supabase directly; screens call these, not `supabase` itself. `lib/types.ts` holds the shared row types; `lib/errors.ts` turns errors into friendly text.
- **Database** (`supabase/migrations`): the source of truth for tables, RLS policies, storage buckets and SQL functions; applied in filename order. Privacy is enforced by RLS, not the client. When joining tables with several FKs between them, use explicit PostgREST FK hints (an ambiguous embed returns HTTP 300 / PGRST201). Edge Functions (excluded from tsc/eslint): `supabase/functions/delete-account`, and `supabase/functions/username-auth` (sign up with just a username – a stand-in `@noemail.peekaboo.invalid` email – and log in by username; rate-limited via `username_auth_log`).
- **Logic duplicated client/server – keep in sync**:
  - Daily drop time: `dropMinute()` in `src/lib/drop.ts` must match `private.drop_minute` in the drop migration. Everyone gets the same local clock time (10:00–22:00) and a 2‑minute window. Drop alerts are *local* scheduled notifications (`lib/notifications.ts`), not server push.
  - Daily dare: `dareFor(day)` in `src/lib/dares.ts` picks from `DARES` by day number; the dare rolls over at `NEW_DARE_HOUR_UTC`. Community overrides come from the `daily_dares` table. `docs/DARES.md` lists the dares; regenerate it when `DARES` changes.
- **Optional native modules**: some features need native code that Expo Go or older APKs lack (video, audio, video thumbnails, Skia scratch reveal, the vision-camera/nitro face lens). They are loaded through guards – `requireOptionalNativeModule` / `TurboModuleRegistry.get` in `components/VideoClipSafe.tsx`, `ScratchRevealSafe.ts`, `lib/voice.ts`, `lib/media.ts`, `lib/faceLens.ts` – with a fallback UI. Follow this pattern for any new native dependency, and import the `*Safe` wrappers, not the real modules.
- **Theme**: `src/theme.ts` (colors, `space`, `radius`, `font`); light/dark follows the user's choice or the phone.
- **Legal**: `legal/*.md` are the canonical Terms / Privacy / Guidelines / Dare Safety Rules. The app shows the copy in `src/lib/legalDocs.ts` (generated by `scripts/sync-legal.mjs`). Bump `TERMS_VERSION` / `DARE_RULES_VERSION` in `src/lib/legal.ts` when users must re-accept.

## Shipping

- **OTA (JS-only changes)** – EAS Update, branch/channel `preview`, runtime `exposdk:58.0.0` (`runtimeVersion.policy: sdkVersion`). Always load `.env` and clear the cache, otherwise the bundle can ship without the Supabase values:
  ```sh
  set -a && . ./.env && set +a
  npx eas-cli@27.1.0 update --branch preview --message "…" --platform all --non-interactive --environment preview --clear-cache
  ```
  Then verify: `strings dist/_expo/static/js/*/*.hbc` (also `strings -el`) must contain the project URL, not `setup-needed.supabase.co`. Pin `eas-cli@27.1.0` (27.2.0 fails to install).
- **Native builds** – needed for new native modules, app.json native config, icons/splash. Profiles in `eas.json`: `preview` (internal Android APK; the APK URL is hard-coded in `src/lib/invite.ts`), `testflight` (iOS store build on the preview channel, `ascAppId` set), `production`. EAS project `@rbaig18s-team/peekaboo`. Keep every Expo package at the version `npx expo install --check` expects: iOS uses prebuilt frameworks, and a mismatch (e.g. `expo-video` vs `expo-modules-jsi`) builds fine but crashes at launch with a dyld "symbol missing".
- **iOS / TestFlight** – App Store Connect API key credentials live in the EAS `production` environment (`EXPO_ASC_*`, `EXPO_APPLE_TEAM_ID`). The Apple team is shared with other apps of the same organisation: never revoke or reuse their certificates, keys or profiles. `docs/TESTFLIGHT.md` has the owner-facing steps.
